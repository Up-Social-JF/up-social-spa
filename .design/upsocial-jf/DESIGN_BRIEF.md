# Design Brief: UpSocial by JF — Agency Website

## Problem

A Munich-based SME owner — a restaurateur, a shop owner, a young startup founder — knows their brand needs better visuals, more reach, maybe a new website. They've been burned by cold corporate agencies that pitch six-figure retainers, or by freelancers who deliver nice photos but vanish after the shoot. They want one trusted person who shoots beautifully _and_ understands the digital game, who speaks German, knows Munich, and won't disappear after the invoice. They land on an agency site, scan for ten seconds, and leave if they can't tell whether it's for them.

## Solution

A photography-led, editorially calm marketing site for **UpSocial by JF** that does three things in the first scroll:

1. **Establishes that a real person — Julian Frey — stands behind the work**, with a portrait and a Munich anchor.
2. **Shows the breadth of capability** (photography → social → ads → web → SEO → e-commerce) without pricing pressure or comparison-table noise, so visitors self-identify which capability they need.
3. **Lets them start a conversation in the channel they already use** — WhatsApp, Instagram, Email, or a direct booking — under a single CTA: **"Jetzt buchen"**.

The site reads like a premium fashion editorial — large, considered photography; muted near-black/off-white/olive palette; restrained motion (fades, scroll-into-view, gentle parallax); generous whitespace. No comparison tables, no "request a custom quote" friction, no agency-stock imagery.

## Experience Principles

1. **Bilder zuerst, Worte zweitens** — photography carries the story; type stays small, calm, and out of the way. _In practice:_ every section opens or anchors on a real photograph; type never competes with the image; H1s are short and editorial, not loud.

2. **Breite zeigen, nicht Pakete verkaufen** — present capabilities as a flat menu of skills, not as a vertical ladder of tiers. _In practice:_ no "Starter / Pro / Done For You" cards; instead 6 capability cards that can be mixed; no prices, only a "Mehr erfahren" path into a per-capability detail page; everything bottoms out on the same single CTA.

3. **Casual einladen, premium liefern** — premium aesthetic, casual entry. _In practice:_ the footer-banner CTA invites a WhatsApp message, not a 12-field RFP form; Julian's headshot is approachable, not corporate; copy is in du/Sie hybrid that errs informal where the brand voice allows; visual restraint communicates the premium half.

## Theming

The site ships with **two complete themes** that share a single trademark accent color. The user switches at any time via a theme toggle in the top nav.

- **Trademark color (constant across themes)**: olive **`#64725F`** — used for accent strokes, links on hover, the JF mark glyph, the active-state indicator on the theme toggle, and any small graphic ornament. Olive **never carries body-size text** in either theme (contrast too low) — only ≥24px display copy or graphic elements.
- **Theme A — Beige (default)**: off-white `#f0efe9` background, near-black `#0a0a0a` foreground. Olive accent. A darker olive variant (token `--accent-deep`, derived in Phase 4) used wherever the brand color must carry body-sized text on this theme.
- **Theme B — Dark**: near-black `#0a0a0a` background, off-white `#f0efe9` foreground. Olive accent. Olive at body-size passes AA against near-black, so `--accent-deep` collapses to plain `--accent` here.
- **Storage location — CSS only.** Both themes are declared as CSS custom properties in `src/index.css`, applied via a class on `<html>` (`.theme-beige` / `.theme-dark`). No theme tokens live in JS or Tailwind config; Tailwind v4's `@theme inline` block reads from the CSS variables. Theme state is persisted in `localStorage` and hydrated synchronously before first paint to prevent flash.
- **Default**: Beige theme on first visit. `prefers-color-scheme: dark` is **not** auto-respected — the brand wants a deliberate choice, not OS-derived.
- **Theme switch animation — circular wipe.** Clicking the theme toggle triggers a circular clip-path reveal originating from the toggle button's coordinates, expanding to cover the viewport over ~600ms with `cubic-bezier(0.65, 0, 0.35, 1)`. Implemented with the View Transitions API (`document.startViewTransition`) where supported (Chrome / Edge / Safari 18+ / Firefox 134+); gracefully falls back to a 200ms cross-fade in older browsers. The wipe reveals the _new_ theme — there is no flash of either state during transition.
- **Themed assets.** The site uses two logo treatments — `logo-wide.svg` (white wordmark, for dark theme) and a dark variant of the same wordmark (for beige theme). The dark wordmark is generated by inverting fill via CSS `currentColor` on the SVG paths, OR a second SVG file is added — Phase 6 picks the cleaner approach. Photography looks good on both themes (warm tones complement both surfaces).
- **Themed motion.** Reduce-motion users get an instant theme swap with no wipe.

## Aesthetic Direction

- **Philosophy**: **Editorial Minimal** — premium fashion magazine meets photographer's portfolio. Closer to Aesop / MR PORTER / _Cereal Magazine_ than to a SaaS landing page. A small dose of business-casual punch from inspiration site `thatlot.co.uk` shows up only in **structural clarity** and **headline confidence** — not in punchy color or punchy motion.
- **Tone**: Confident, calm, deliberate. Trust-building. German B2B-appropriate but never stiff. Avoids superlatives. Shows, doesn't shout.
- **Reference points**:
  - `thatlot.co.uk` — for clarity of structure, single-CTA discipline, numbered case-study language
  - Aesop, MR PORTER, _Cereal Magazine_, Loro Piana — for editorial restraint, type-image balance, muted palette
  - `sociallyin.com` — for capability framing (not visual style)
- **Anti-references**:
  - Squarespace template agencies (generic gradients, stock business imagery)
  - Bold "wow" SaaS landing pages (animated gradients, Mesh hero, big buttons)
  - Cold corporate consultancies (blue palettes, stock handshakes, dense pricing tables)
  - Punchy creative-agency sites with chaotic motion and rainbow palettes

## Existing Patterns

This site is being built into a freshly-initialized Vite + React 19 + Tailwind v4 + shadcn template. Brand-specific design language must be introduced; shadcn defaults must be overridden. Treat current state as a clean substrate, not a constraint.

- **Typography**: Currently `system-ui` fallback. **Will replace with Plus Jakarta Sans** (variable, weights 300–700) loaded from Google Fonts or self-hosted. No serif at launch; monospace only for tiny utility tags if needed.
- **Colors**: Currently default shadcn neutral palette in OKLCH (will be replaced in Phase 4). Brand palette is fixed: **near-black `#0a0a0a`**, **off-white `#f0efe9`**, **olive `#64725F`** (trademark). Two complete themes will be authored as CSS custom properties in `src/index.css`: `.theme-beige` (default) and `.theme-dark`. Olive is the constant trademark accent across both. The existing `.dark` class variant in `index.css` will be replaced with explicit theme classes — no `prefers-color-scheme` auto-derivation.
- **Spacing**: Tailwind v4 default spacing scale. Editorial layouts will need a slightly more generous rhythm than shadcn defaults — likely a custom `--spacing` base around `0.25rem` × multiples of 4/8/12/24 for editorial gutters.
- **Components**: Only `button.tsx` (shadcn Button) currently installed. Will need: `dialog`, `sheet`, `accordion`, `input`, `textarea`, `label`, `separator`, `card`. All to be added via `pnpm dlx shadcn@latest add <name>`. No design conventions exist yet — this brief defines them.
- **Routing**: `react-router` v7 already wired in `src/routes/Routes.tsx`. Multi-page site will use it.
- **Motion**: `motion` v12 (Framer Motion successor) installed and ready.
- **State**: Redux Toolkit installed. Likely used for the global contact panel state, not for content (content stays static / file-based).
- **Logos available now**: `public/logo-wide.svg` (white "UpSocial" wordmark for dark backgrounds), `public/logo.svg` (JF monogram in dark rounded square for light backgrounds & favicon). Any future versions can be added; layout reserves wordmark height accordingly.

## Key Interactions

**Single global CTA → ContactPanel.** Every "Jetzt buchen" button on every page opens the same right-slide sheet (or full-screen mobile modal). Inside: 4 contact options as large editorial-style links — WhatsApp, Instagram, Email, "Termin buchen (bald verfügbar)". Each is a real link except the booking placeholder, which shows a quiet _"In Kürze verfügbar — schreib uns gerne direkt"_ line. Sheet state lives in Redux so any component can trigger it.

**Hero scroll behavior.** Hero photo has gentle parallax on Y-axis (≤ 50px translation across the hero scroll range). Headline and CTAs fade-in on mount with staggered delay (200ms · 350ms · 500ms). Scroll indicator at the bottom of hero gently bobs and fades out as the user scrolls past 100vh.

**Section reveals.** Every section below the hero uses `MotionInView` wrapper: fade + 16px translate-up, triggered when 20% in viewport, once-only. Stagger child elements (e.g., capability cards) by 80ms each.

**Capability card hover.** On desktop hover: numeral grows slightly (scale 1.05), bullet list fades to ~70% opacity, "Mehr erfahren" arrow translates 4px right. Card border/background does not change. Mobile: tap goes directly to detail page.

**Gallery interactions.** Theme tile hover: image scales 1.03 inside its frame, theme name underline draws left-to-right. Click → theme detail page. Inside theme detail: clicking any image opens Lightbox. Lightbox supports keyboard navigation (← / → / ESC) and swipe on touch.

**Mobile nav.** Hamburger toggles a right-slide sheet with full nav links stacked, with CTA "Jetzt buchen" as the largest item. Closes on link click.

**Theme switch.** User clicks ThemeToggle in the top nav. The browser captures the current frame, swaps `.theme-beige` ↔ `.theme-dark` on `<html>`, and animates a circular reveal of the new theme outward from the toggle's center coordinates over ~600ms. During the wipe, both old and new theme are visible (clipped); the wipe finishes covering the viewport, leaving the new theme. The toggle icon itself flips with a 200ms scale + opacity cross-fade independent of the wipe. Per-element transition rules: backgrounds, borders, and text colors do **not** use a CSS `transition` on the variables themselves — the wipe handles all visual blending in one synchronized motion.

**Top-nav scroll behavior.** Above hero (top of page): transparent background, white text/wordmark. Once scrolled past 80vh: solid off-white background, near-black text, subtle border-bottom. Transition: 200ms ease.

## Responsive Behavior

- **Mobile (< 640px)**: Single column. Hero is 100vh full-bleed image with stacked text overlay. CapabilityGrid is 1-col, cards full-width with reduced bullet padding. Founder section stacks (image on top, text below). Gallery grid is 2-col masonry. Top nav collapses to hamburger + wordmark. Lightbox is full-screen with bottom-bar controls.
- **Tablet (640–1024px)**: 2-col grids for capabilities and gallery. Hero remains full-bleed but adds a 60% overlay panel on left for type. Founder section becomes image-left/text-right. Top nav shows links inline.
- **Desktop (≥ 1024px)**: 3-col capability grid, full editorial layouts. Hero uses a 7/12 · 5/12 split (image dominates, type panel sits in bottom-left third). Generous gutters (≥ 96px outer padding). ContactPanel becomes a right-slide sheet, ~480px wide, instead of a full modal.
- **Wide (≥ 1440px)**: Cap content width at 1440px max with auto margins; gutters scale up.
- **Hero photo behavior**: aspect ratios swap — 16:9 desktop, 4:5 mobile — using `<picture>` srcset.

## Accessibility Requirements

- **Contrast**: Text on near-black background must hit **WCAG AA 4.5:1**. The brand olive `#64725F` against off-white `#f0efe9` is borderline (~3.6:1) — used for **decorative/large-only** text (≥ 24px) or as a graphic element. For body copy on dark sections, off-white `#f0efe9` against near-black `#0a0a0a` exceeds AAA. Verify all combinations in Phase 4 token generation.
- **Keyboard navigation**: All interactive elements reachable via Tab in DOM order. Focus rings visible on all focusable elements (custom ring matching olive accent at 2px outset). ESC closes Lightbox and ContactPanel. Arrow keys navigate Lightbox.
- **Screen readers**: Semantic landmarks (`<header>`, `<main>`, `<nav>`, `<footer>`). Each gallery image has descriptive `alt` text in German. The CTA "Jetzt buchen" has an `aria-label` clarifying it opens a contact panel. Decorative images use `alt=""`.
- **Motion preference**: Respect `prefers-reduced-motion` — disable parallax, fade-in, and stagger; replace with instant appearance.
- **Language**: `<html lang="de">`. All copy in German. Foreign words (capability names like "Social Media") get no special treatment.
- **Form labels**: If a contact form is added later, every input has an associated `<label>`, and errors are announced via `role="alert"`.
- **Lightbox**: Trap focus inside when open; return focus to triggering image on close.
- **Touch targets**: Minimum 44×44px for all interactive elements on mobile.

## Out of Scope

- **Pricing display.** Tier prices are explicitly not shown anywhere in this build. Future addition handled separately.
- **Real client testimonials and logos.** Section structure is _not_ built at launch (no placeholder quotes). Add when ≥ 4 real quotes exist.
- **Blog / journal / case-study writeups.** No editorial content section. May be added in a later phase.
- **CMS integration.** Content is hardcoded in TypeScript constants. Sanity (or alternative) integration is a separate project.
- **i18n / English version.** German only. EN deferred until demand is demonstrated.
- **Live Calendly / Cal.com booking.** Placeholder only — "In Kürze verfügbar". Real embed added once Julian sets up his account.
- **Server-side form submission.** No backend at launch — all CTAs route to external channels (WhatsApp, IG DM, mailto, future Calendly). No email-collection form is wired.
- **Cookie banner & full DSGVO consent flow.** Out of scope for this prototype build (umami is GDPR-friendly, no consent UI needed for analytics-only). Will be added if marketing tags are added later.
- **Newsletter signup.** Not part of this brief.
- **Search functionality.** No site-wide search — content too small.
- **Authentication / member areas.** None.
- **Migration to Astro / Next.js.** This build lives in the current Vite/React template as a high-fidelity prototype; production migration is a separate project with its own brief.
